# QQ 账号保活方案

针对 5 个以上小号矩阵的长期维护方案。核心原则：**工具管账、人工登录**。

## 一、规则依据

腾讯官方《QQ号码规则》与客服 FAQ 给出的回收条件：

| 号码类型 | 回收条件 |
|---|---|
| 普通号 | 注册后 3 天未登录 / 登录后 45 天未登录 / **3 个月未登录** |
| 精品靓号 | 会员到期超过 **30 天**（2020-07-17 前注册的为 90 天） |
| 普通靓号 | 会员到期不影响使用，不回收 |
| 冻结账号 | 冻结后 **30 天内**未完成验证解冻即可能被回收 |

关键判断：**不存在"开会员免登录回收"的官方条款**。会员解决的是靓号续费压力，不替代登录行为。

## 二、安全余量设计

官方窗口是 90 天，方案把触发线设在 **30 天**。这样即使某次出差、生病、忘记处理，也还有至少 60 天缓冲，永远不会逼近 45 天这条实际风险线。

```
0 ────────── 30 ──── 45 ────────────── 90
   安全区      缓冲带    官方回收判定区
   ↑ 保活触发线
```

## 三、工具使用

依赖 Python 3.9+ 标准库，无需安装任何第三方包。

```bash
python qq_keeper.py init                      # 初始化台账（同目录生成 qq_keeper.db）

python qq_keeper.py add 123456 \
    --alias 小号A --type liang \
    --phone 13800000000 \
    --host 模拟器-MuMu \
    --vip-expire 2026-11-15 \
    --last-login 2026-10-01

python qq_keeper.py list                      # 全量台账 + 到期状态
python qq_keeper.py check                     # 只输出需要处理的号
python qq_keeper.py touch 123456              # 登录后记录，计时归零
python qq_keeper.py touch all                 # 批量记录（一次性全都在线时）
python qq_keeper.py set 123456 --host 实体机 --phone 13800000000   # 更新已存在账号的字段
python qq_keeper.py import template.csv       # 批量导入
python qq_keeper.py export backup.csv         # 导出备份
```

小号数量多时推荐先把账号填进 `template.csv`，一次性 `import` 进去。

## 四、自动化提醒

```bash
python qq_keeper.py install-task
```

注册 Windows 计划任务 `QQKeeperRemind`，每日 10:00 执行一次 `check`：**没事不打扰，有事才弹右下角气泡**。若报权限不足，以管理员身份重跑一次。

## 五、多号矩阵的安全红线

账号一多，回收之外的风险会上升。以下建议按重要性排序：

1. **固定登录环境**。所有保活登号都在同一台机器、同一个家庭宽带 IP 上完成。异地 IP（云服务器、公司专线）切换极易触发安全模式。
2. **同设备登录硬上限：Windows 客户端默认最多同时挂 10 个**（由 `TXPlatform.exe` 进程控制，登录第 11 个会直接提示"超过QQ登录个数限制"被拒）。5 个号挂一台机器完全合规。但新号/异地号首次登录仍建议错峰、固定家庭宽带 IP，避免瞬时多号触发安全验证；超过 10 个才需要换设备、虚拟机或分时段轮换。

   额外手段：手机 QQ 的**关联账号**功能（最多关联 2 个）会让被关联号显示为在线且"当天有登录使用"、不被回收，但不独立在线、不加速等级，可作为低维护的保活补充。
3. **只使用官方客户端**。不要用第三方协议库、机器人框架、接码平台、付费代挂。腾讯明文禁止且持续封堵，一旦被判定异常 → 冻结 → 30 天未解冻 → 回收，比不保活更糟。
4. **密码交给密码管理器**，不要图省事在脚本里保存明文密码。
5. **绑定手机号是生命线**。手机号停用是比回收更常见的丢号原因：一旦需要验证或申诉，号码已注销就基本救不回来。台账里的 `绑定手机` 字段就是为此存在。
6. **每季度做一次全量体检**：全部登录一遍、确认手机号可用、`export` 一份备份。

## 六、日常节奏

| 频率 | 动作 |
|---|---|
| 每周 | 若采用轮换策略则登录一批并执行 `touch`；常挂载体无需此步 |
| 每天 10:00 | 计划任务自动扫描，超期才弹窗 |
| 每季度 | 全量体检 + `export` 备份 |

处理完 accounts 后立即 `touch` 是整套流程最关键的闭环动作——**不 touch 等于没登录**。

## 七、超过 10 个号的处置

记住密码上限与同时在线上限一致（约 7–10 个，以你环境实测为准），轮换必然撞掉已存密码槽位。三条处置路线：

> 重要风险提示（2026-10 核实）：腾讯《用户协议》明确禁止非官方多开 / 分身 / 虚拟化工具登录 QQ，且风控对「虚拟化环境 + 低权重小号 + 同一公网 IP 多号」高度敏感。本地安卓模拟器正是这三类特征的叠加——小号（注册短、无实名、无好友）在此类环境登录极易被冻结甚至封号，比「被回收」更糟。因此模拟器只适合挂高权重老号；小号矩阵应优先真机 / 云手机 / 定期扫码登录，而非本地模拟器。

1. **拆载体常挂（首选，零重输）**。总号数 N 按每载体 10 个拆成 ceil(N/10) 个载体（实体机 / 虚拟机 / 安卓模拟器各算一个）。每个载体内 ≤10 个号全部记住密码、长期在线，永不轮换，从根本上消除重输密码问题。代价是一次性的多载体管理。

   **台账统一在宿主机**：模拟器/虚拟机都是宿主机上的进程，把 `qq_keeper.db` 放在宿主机、由宿主机统一跑脚本即可。无论号挂在哪个载体，登录后回到宿主机执行 `touch <uin>` 就完成记录。每个号用 `--host` 标记其常挂载体（如 `实体机` / `VM-win` / `模拟器-MuMu`），`list` / `check` / 提醒里都会显示载体，方便轮换与排障。跨**物理机**时才需要把 db 放到共享盘或网络路径。
2. **单台轮换 + 扫码登录（免密码）**。仍只用一台机器但分两组轮流在线，轮换时用手机 QQ 扫码确认登录，全程不输密码。前提是 **QQ 安全中心 APP 绑定了全部号**（可绑定多个，且扫码授权不要求该号在手机 QQ 内在线），轮换时在其中选择目标号扫码；PC 端该号已验证过、开启登录保护后同机再次登录通常无需短信验证。代价是每次轮换需手边有手机。
3. **密码管理器兜底**。用 KeePass / Bitwarden 存储密码，借助自动输入（Auto-Type）匹配 QQ 登录窗口填表，应对扫码不便的场景。

若这些小号只需"不被回收"而不要求 PC 随时可用，最低维护方案是：**主力号 PC 常挂 + 其余号手机 QQ 关联（最多 2 个）计入活跃**，剩余号每 30 天扫码登录一次即可。
